# Implementation - Talent / Soldier Selection Engine

This document describes the implementation that exists in this repository. It is
an operational service runbook.

## Run

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
uvicorn system2.api:app --reload --port 8002
```

Health:

```bash
curl http://127.0.0.1:8002/v1/healthz
```

Score:

```bash
curl -X POST http://127.0.0.1:8002/v1/score \
  -H 'content-type: application/json' \
  -d '{"mission_id":"raid-tonight","candidate_count":80,"seed":42}'
```

## Test

```bash
pytest
```

The current test suite covers response shape, kill-switch blocking, strict
request validation, protected-attribute exclusion from feature hashing,
counterfactual fairness invariance, proxy-feature detection, group fairness
metrics, low-confidence disagreement behavior, and audit hash-chain validation.

## Data Inputs

`ScoreRequest` accepts either:

- `candidates`: explicit `Soldier` records supplied by the caller
- `candidate_count` plus `seed`: deterministic synthetic records generated by
  `data.generate_soldiers`

Operational integrations should supply candidates directly. Synthetic
generation exists for local development, repeatable tests, and disconnected
environments.

`roles` can be supplied explicitly. If omitted, `data.default_roles()` provides
the standard 14-slot roster.

## Module Responsibilities

`api.py`

Defines FastAPI routes. `/v1/score` and `/v1/healthz` are canonical. `/score`
and `/health` are compatibility aliases. Runtime errors from the service become
HTTP `423` when the engine is disabled; assignment failures become HTTP `422`.

`service.py`

Coordinates the full scoring transaction. It checks the kill switch, builds the
candidate/role inputs, computes scores, solves primary and secondary rosters,
runs fairness audits, builds trace metadata, writes audit records, and returns a
`RosterRecommendation`.

`models.py`

Holds the Pydantic contracts. All models inherit strict extra-field rejection.
Response models include uncertainty, model disagreement, fairness, career, and
trace fields.

`data.py`

Provides default roles and deterministic synthetic candidates. The generated
records follow the feature dictionary and include protected attributes only so
fairness audits can run.

`scoring.py`

Contains the operational scoring contract: role-fit calculation,
TabPFN-compatible probability, Bayes-compatible pooled probability, confidence
blend, protected-attribute-excluding feature hash, and Hungarian assignment.

`fairness.py`

Runs counterfactual flips, proxy-feature checks, demographic-parity deltas, and
equalized-odds proxy deltas. Protected attributes are read here for measurement
only.

`narrative.py`

Builds explanations and risk factors from already-computed deterministic
outputs. It never mutates rank, scores, or assignment.

`career.py`

Returns a five-year forecast for the highest-fit selected soldier. This is a
secondary operational output and does not affect roster assignment.

`calibration.py`

Builds trace summaries for calibration bins and model-disagreement histogram.

`audit.py`

Writes redacted hash-chained JSONL records. The default path is
`/tmp/system2_audit.jsonl`; set `SYSTEM2_AUDIT_LOG` in deployed environments.

`registry.py`

Centralizes model adapter versions, prompt version hash input, and DoD AI Ethics
mapping.

## Operational Safeguards

- The kill switch blocks all scoring paths.
- Protected attributes are excluded from scoring and feature hashes.
- Unit and MOS are hashed in persisted audit payloads.
- Confidence and model disagreement are mandatory response fields.
- Fairness audit results are returned on every successful score response.
- Narrative code explains only; it does not decide.
- Admin endpoints must be protected outside this package.

## Synthetic Data Export

```bash
python scripts/generate_synthetic.py --n 5000 --seed 42
```

The script writes JSONL with one metadata line followed by `Soldier` records.
The default output path is `artifacts/synthetic-cohort.jsonl`.

## Known Gaps

- No built-in authentication or authorization.
- No persistent feature warehouse.
- Deterministic model adapters stand in for heavier trained adapters.
- Career forecasting is rule-based and secondary to roster assignment.
- System 1 and System 3 integrations are documented boundaries, not implemented
  clients in this package.
